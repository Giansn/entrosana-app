# Modules and areas

A module is a piece of teaching material with a page in the catalogue: a title, a lede, a text, facts, links, a state and the people who contribute to it.

## Areas

The catalogue sorts modules into three areas, shown as tabs on the Modules page:

| Area | In a proposal | Examples |
|---|---|---|
| Nature | `nature-based` | outdoor lessons, gardens, weather, animals |
| Social | `social` | groups, conflict, values, community |
| Technical | `technical` | tools, code, machines, measurement |

A proposal may also say `other`; the team places it.

## State

| State | Shown as | Meaning |
|---|---|---|
| `idea` | only an idea | a direction, not yet usable in class |
| `development` | still in development | usable with care, changing |
| `finished` | finished | stable, ready to run |

A newly published module starts as *still in development*. Its contributors change the state on the module page.

## What a module page holds

- Title, lede and the longer text.
- Facts: up to twelve label and value pairs, for example age group, duration, group size.
- Links: up to eight lines of what you get, each a file or a page.
- State, area and the date of the last update.
- The contributors, each linked to their public page.
- A point button and a report form.

## Points and reports

Anyone signed in can give a module one point, and take it back. The count shows on the card. Anyone can report a module through the form on its page; the report goes to sygnif@entrosana.com and the team answers.

## Contributors

A module has one or more contributors. The person whose proposal was published is the first; further contributors are added by e-mail address of an account with contributor standing. Every contributor can edit the module, see [Edit a published module](/how-to/edit-a-module).
